MDSE 0.8.0 import renderer

Writes one package slice or the complete planned model into a fresh generated MDSE 0.8.0 base. The base release and all three runtime schemas are validated before writing. Local parts, endpoints, connections and flows use governed Local Model 0.3 records. A valid fresh base may be selected while its vault identity is still uninitialized, but model generation remains blocked until the explicit initialization step completes. Diagram artifacts are intentionally deferred; linked-document rows are reconciled and any extraction failure is logged explicitly.

Decode-only needs only the QEAX and a PASS plan (no output folder). It runs the same identity, path-planning and attachment code as the whole-model write, writes nothing, downloads Attachment Reconciliation - Decode Only.csv, and reports PASS only against the loaded attachment_benchmark.json.

Use a fresh generated MDSE 0.8.0 base. Do not select Test_Vault_ or an existing imported model. Build a PASS plan first, then select the output. The importer requires relationships 1.35, element-types 1.17, Local Model 0.3, and the pinned MDSE Bootstrap + Workbench runtime stack. A newly extracted base with vault_uid: UNINITIALIZED is valid input to the initialization step but cannot receive model content until initialization succeeds. The importer imposes no total generated-path-length limit and no generated-file-count limit per folder. Only the physical filesystem component limit is enforced. Nested first-class elements are placed under folders named for their parent elements, and imported note filenames are unique across the entire vault (case-insensitive), including names already present in the base.
