## Important findings
1. **Archive coverage is now discoverable, but not semantically read end-to-end.** The MOC references every one of 1,165 archived paths from the migration manifest. This audit inspected representative high-value contracts, not every implementation line.
2. Existing v1 contains substantial finished behavior and tests; the v2 backlog should first check reuse opportunities rather than write new code by default.
3. V1 architecture assumed Markdown/YAML primary model; approved v2 uses bottom-of-note SysML text. Reuse operating safeguards and UI interaction behavior, **not** the old formal model authority.
4. Plugin update policy historically assumed centrally pinned runtime, while v2 explicitly preserves approved user preferences. Migration must implement field-level ownership instead of copying v1 replacement behavior unchanged.
5. BOM A01–A14 contains proposals and partial validation. A file or fixture is not proof of approval or a shipping v2 writer.
